# Учёт носков на складе (тестовое задание Райффайзен CIB)

Простой HTTP-сервис на Java для учёта прихода, расхода и остатков носков на складе.

Исходное задание: https://github.com/Hexlet/ru-test-assignments/blob/main/java/raiffeisen/cib-interns-test-task.md

## Что делаю (выбранный объём)

- Все 3 HTTP-метода из условия: POST /api/socks/income (приход носков), POST /api/socks/outcome (списание со склада) и GET /api/socks (подсчёт остатка по цвету и содержанию хлопка: moreThan, lessThan, equal).
- Реализация на стандартной Java с использованием встроенного HttpServer из JDK, без Spring и внешних библиотек.
- Хранение данных в оперативной памяти в обычном списке ArrayList.
- Проверка входных данных и возврат кодов ответа 200, 400, 405 и 500.

## Что не делаю и почему

- Подключение базы данных PostgreSQL и миграций Liquibase или Flyway — на настройку не хватит отведённых 6–8 часов, а основная логика склада работает и с хранением в памяти.
- Упаковка в Docker и деплой на облачный сервер — вынесено за рамки базового сценария.
- Форк и pull request в репозиторий компании — задание взято из каталога Hexlet, поэтому решение оформлено в отдельном открытом репозитории.

## Как запустить

- Для запуска не нужны внешние библиотеки, базы данных или Docker — достаточно установленной JDK 11+.
- Запуск через IntelliJ IDEA: откройте проект в среде разработки, перейдите в файл Main.java и нажмите зелёную кнопку Run рядом с методом main.
- Запуск через консоль (из папки src): скомпилируйте файлы командой javac -encoding UTF-8 *.java и запустите сервер командой java Main.
- После запуска сервер работает по адресу http://localhost:8080 (данные хранятся в оперативной памяти и очищаются при перезапуске).

## Как проверял

- Запускал сервер в IntelliJ IDEA и отправлял тестовые HTTP-запросы через встроенный терминал (Windows PowerShell; перед запуском можно выполнить chcp 65001 для корректного отображения кириллицы).
- Приход носков (POST /api/socks/income): curl.exe -i -X POST http://localhost:8080/api/socks/income -H "Content-Type: application/json" -d '{\"color\":\"red\",\"cottonPart\":80,\"quantity\":10}' (ожидаемый ответ: 200 OK, Приход носков добавлен).
- Списание носков со склада (POST /api/socks/outcome): curl.exe -i -X POST http://localhost:8080/api/socks/outcome -H "Content-Type: application/json" -d '{\"color\":\"red\",\"cottonPart\":80,\"quantity\":4}' (ожидаемый ответ: 200 OK, Носки списаны со склада).
- Проверка остатка по фильтру (GET /api/socks): curl.exe -i "http://localhost:8080/api/socks?color=red&operation=moreThan&cottonPart=50" (ожидаемый ответ: 200 OK, 6).
- Граничные случаи: отправлял пустое тело запроса, процент хлопка вне диапазона 0–100, GET-запрос без параметра cottonPart, неверный HTTP-метод и попытку списать больше пар, чем доступно на складе.

## Коды ответа сервиса

- 200 — запрос успешно выполнен (приход добавлен, носки списаны или возвращено число остатков).
- 400 — ошибка во входных данных (пустое тело, некорректный JSON, не указан цвет или операция, отсутствует или неверно задан cottonPart или quantity, процент хлопка вне 0–100, количество меньше или равно 0, недостаточно носков на складе).
- 405 — использован неверный HTTP-метод (например, GET вместо POST для прихода или расхода).
- 500 — непредвиденная внутренняя ошибка сервера.
